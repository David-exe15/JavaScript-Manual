Chapter 01

Variables & Data Types

Variables are named containers that store data. In JavaScript, you declare them with var, let, or const — each with different rules.

BEGINNER

Declaring Variables

Modern JavaScript uses let for values that change, and const for values that stay fixed. Avoid var in new code — it has confusing scoping rules.

EXAMPLE — variable declarations 
// const — value cannot be reassigned
const name = "Alice";
const PI = 3.14159;

// let — value can change
let score = 0;
let isLoggedIn = false;

score = 42;   // ✓ allowed with let
// name = "Bob"; ← ✗ TypeError: const cannot be reassigned

EXAMPLE — typeof operator 
typeof "hello"     // → "string"
typeof 42          // → "number"
typeof true        // → "boolean"
typeof undefined   // → "undefined"
typeof null        // → "object"  ← famous JS quirk!
typeof {}          // → "object"
typeof []          // → "object"
typeof function(){} // → "function"

String Methods

EXAMPLE — string manipulation 
const msg = "Hello, World!";

msg.length               // → 13
msg.toUpperCase()        // → "HELLO, WORLD!"
msg.toLowerCase()        // → "hello, world!"
msg.includes("World")    // → true
msg.replace("World", "JS") // → "Hello, JS!"
msg.slice(0, 5)          // → "Hello"
msg.split(", ")          // → ["Hello", "World!"]
msg.trim()               // removes whitespace from both ends

// Template literals — use backticks
const user = "Alice";
const greeting = `Hello, ${user}! You have ${3 + 2} messages.`;
// → "Hello, Alice! You have 5 messages."
💡
Template Literals

Always prefer template literals (backticks) over string concatenation with +. They're more readable and support multi-line strings naturally.

Chapter 02

Operators

Operators perform actions on values. JavaScript has arithmetic, comparison, logical, and assignment operators — each with important subtleties.

BEGINNER

Arithmetic Operators

EXAMPLE — arithmetic 
10 + 3   // → 13  (addition)
10 - 3   // → 7   (subtraction)
10 * 3   // → 30  (multiplication)
10 / 3   // → 3.333... (division)
10 % 3   // → 1   (modulo — remainder)
2  ** 8  // → 256 (exponentiation)

let x = 5;
x++;  // x becomes 6 (post-increment)
x--;  // x becomes 5 (post-decrement)
++x;  // increment BEFORE returning value

Comparison Operators & Type Coercion

⚠️
Always use === not ==

The == operator does type coercion (converts types before comparing), which causes surprising bugs. Always use === (strict equality) which checks both value AND type.

EXAMPLE — equality trap 
// == (loose equality) — AVOID
0   ==  false  // → true  🤔
""  ==  false  // → true  🤔
1   ==  "1"    // → true  🤔
null == undefined // → true 🤔

// === (strict equality) — USE THIS
0   === false  // → false ✓
""  === false  // → false ✓
1   === "1"    // → false ✓

// Other comparisons
5 >  3   // → true
5 >= 5   // → true
2 !== 3   // → true (strict inequality)

Logical Operators

EXAMPLE — logical operators 
// AND (&&) — both must be true
true && true   // → true
true && false  // → false

// OR (||) — at least one must be true
false || true  // → true
false || false // → false

// NOT (!) — inverts the value
!true          // → false
!false         // → true

// Nullish coalescing ?? — fallback for null/undefined
const username = null ?? "Guest";  // → "Guest"
const port     = undefined ?? 3000; // → 3000

// Optional chaining ?. — safe property access
const user = null;
user?.name      // → undefined (no crash!)
user.name       // → TypeError 💥

Chapter 03

Control Flow

Control flow lets your program make decisions and repeat tasks. The building blocks are if/else, switch, and loops.

BEGINNER

if / else if / else

EXAMPLE — branching logic 
const score = 78;

if (score >= 90) {
  console.log("A — Excellent!");
} else if (score >= 80) {
  console.log("B — Good job");
} else if (score >= 70) {
  console.log("C — Passing");   // ← this runs
} else {
  console.log("F — Try again");
}

// Ternary operator — compact if/else for one value
const status = score >= 60 ? "Pass" : "Fail";
console.log(status); // → "Pass"

switch Statement

EXAMPLE — switch 
const day = "Monday";

switch (day) {
  case "Monday":
  case "Tuesday":
  case "Wednesday":
  case "Thursday":
  case "Friday":
    console.log("Weekday — work time");
    break;
  case "Saturday":
  case "Sunday":
    console.log("Weekend — relax!");
    break;
  default:
    console.log("Unknown day");
}

Loops

EXAMPLE — for, while, for...of 
// Classic for loop
for (let i = 0; i < 5; i++) {
  console.log(i); // 0, 1, 2, 3, 4
}

// while loop
let count = 10;
while (count > 0) {
  console.log(count);
  count -= 2;
}

// for...of — iterate over array values
const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
  console.log(fruit);
}

// for...in — iterate over object keys
const person = { name: "Bob", age: 30 };
for (const key in person) {
  console.log(key, person[key]);
}

// break and continue
for (let i = 0; i < 10; i++) {
  if (i === 3) continue; // skip 3
  if (i === 7) break;    // stop at 7
  console.log(i);         // 0,1,2,4,5,6
}

Chapter 04

Functions

Functions are reusable blocks of code. They are first-class citizens in JavaScript — you can assign them to variables, pass them as arguments, and return them from other functions.

BEGINNER

Function Declaration vs Expression vs Arrow

EXAMPLE — 3 ways to define functions 
// 1. Function Declaration — hoisted (can call before definition)
function greet(name) {
  return `Hello, ${name}!`;
}

// 2. Function Expression — assigned to a variable
const square = function(x) {
  return x * x;
};

// 3. Arrow Function — concise, modern syntax
const add = (a, b) => a + b;  // implicit return

const multiply = (a, b) => {   // explicit return needed with braces
  const result = a * b;
  return result;
};

console.log(greet("World"));  // → "Hello, World!"
console.log(square(9));       // → 81
console.log(add(3, 4));       // → 7

Default Parameters & Rest

EXAMPLE — parameters 
// Default parameters
function createUser(name, role = "viewer", active = true) {
  return { name, role, active };
}

createUser("Alice");
// → { name: "Alice", role: "viewer", active: true }

createUser("Bob", "admin");
// → { name: "Bob", role: "admin", active: true }

// Rest parameters — collect remaining args into an array
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}

sum(1, 2, 3);          // → 6
sum(1, 2, 3, 4, 5);     // → 15
🌟
Single Responsibility Principle

A good function does ONE thing well. If you need to say "and" when describing what it does, split it into two functions.

Chapter 05

Arrays

Arrays are ordered lists. JavaScript arrays can hold any mix of types and come with a rich set of built-in methods.

BEGINNER

Creating & Accessing Arrays

EXAMPLE — array basics 
const nums = [10, 20, 30, 40, 50];

nums[0]          // → 10 (first element)
nums[4]          // → 50 (last element)
nums.length      // → 5
nums.at(-1)      // → 50 (last, modern way)

// Adding / Removing
nums.push(60);    // add to end → [10,20,30,40,50,60]
nums.pop();       // remove from end → returns 60
nums.unshift(0); // add to start → [0,10,20,30,40,50]
nums.shift();    // remove from start → returns 0

// Slicing & Splicing
nums.slice(1, 3)   // → [20, 30] (doesn't modify original)
nums.splice(2, 1) // removes 1 element at index 2

Powerful Array Methods

EXAMPLE — map, filter, reduce, find 
const numbers = [1, 2, 3, 4, 5, 6, 7, 8];

// map — transform each element
const doubled = numbers.map(n => n * 2);
// → [2, 4, 6, 8, 10, 12, 14, 16]

// filter — keep only matching elements
const evens = numbers.filter(n => n % 2 === 0);
// → [2, 4, 6, 8]

// reduce — accumulate into one value
const total = numbers.reduce((acc, n) => acc + n, 0);
// → 36

// find — first match
const firstBig = numbers.find(n => n > 5);
// → 6

// some / every — boolean checks
numbers.some(n => n > 7);    // → true (at least one)
numbers.every(n > 0);      // → true (all positive)

// sort (with comparator for numbers!)
[3, 1, 4, 1, 5].sort((a, b) => a - b); // → [1,1,3,4,5]

// flat — flatten nested arrays
[1, [2, [3, [4]]]].flat(Infinity); // → [1,2,3,4]

Chapter 06

Objects

Objects are collections of key-value pairs. They model real-world entities and are the backbone of JavaScript data structures.

BEGINNER

Creating & Using Objects

EXAMPLE — object fundamentals 
const car = {
  make:  "Toyota",
  model: "Supra",
  year:  2023,
  color: "red",
  describe() {
    return `${this.year} ${this.make} ${this.model}`;
  }
};

// Dot notation (preferred)
car.make        // → "Toyota"

// Bracket notation (useful for dynamic keys)
const key = "model";
car[key]        // → "Supra"

// Adding / modifying / deleting
car.mileage = 0;        // add
car.color = "blue";    // modify
delete car.color;      // delete

car.describe() // → "2023 Toyota Supra"

Destructuring, Spread & Object Methods

EXAMPLE — modern object patterns 
const user = { name: "Alice", age: 30, city: "London" };

// Destructuring — extract into variables
const { name, age, city = "Unknown" } = user;

// Spread — copy or merge objects
const updated = { ...user, age: 31, country: "UK" };

// Object.keys / values / entries
Object.keys(user)    // → ["name", "age", "city"]
Object.values(user)  // → ["Alice", 30, "London"]
Object.entries(user) // → [["name","Alice"],["age",30],...]

// Check if key exists
"name" in user       // → true
user.hasOwnProperty("age") // → true

Chapter 07

Scope & Closures

Scope determines where variables are accessible. Closures are functions that "remember" the environment they were created in — one of JavaScript's most powerful features.

INTERMEDIATE

Variable Scope

EXAMPLE — scope levels 
let global = "I'm everywhere";  // global scope

function outer() {
  let outerVar = "outer";  // function scope

  function inner() {
    let innerVar = "inner"; // function scope (inner)

    // Can access all parent scopes
    console.log(innerVar);  // ✓ "inner"
    console.log(outerVar);  // ✓ "outer"
    console.log(global);    // ✓ "I'm everywhere"
  }

  // Cannot access inner's variables
  // console.log(innerVar); ← ReferenceError
  inner();
}

// Block scope with let/const
for (let i = 0; i < 3; i++) {
  // i is scoped to this block
}
// console.log(i); ← ReferenceError with let (but works with var!)

Closures

EXAMPLE — closures in action 
// A closure "closes over" its surrounding variables
function makeCounter() {
  let count = 0;  // private state!

  return {
    increment: () => ++count,
    decrement: () => --count,
    value:     () => count
  };
}

const counter = makeCounter();
counter.increment(); // count → 1
counter.increment(); // count → 2
counter.decrement(); // count → 1
counter.value();     // → 1

// Each call to makeCounter creates its OWN count
const counter2 = makeCounter();
counter2.increment(); // its own count → 1
counter.value();      // still 1 (independent!)

// Practical: function factory
const multiply = (factor) => (n) => n * factor;

const double = multiply(2);
const triple = multiply(3);

double(5);  // → 10
triple(5); // → 15

Chapter 08

Higher-Order Functions

Higher-order functions accept other functions as arguments or return them. They unlock a functional programming style that leads to cleaner, more composable code.

INTERMEDIATE
EXAMPLE — callbacks & composition 
// Functions as arguments (callbacks)
function applyTwice(fn, value) {
  return fn(fn(value));
}

applyTwice(x => x + 3, 10); // → 16
applyTwice(x => x * 2, 5);  // → 20

// Compose — chain functions right-to-left
const compose = (...fns) =>
  (x) => fns.reduceRight((v, f) => f(v), x);

const addOne = x => x + 1;
const double = x => x * 2;
const square = x => x ** 2;

const transform = compose(double, addOne, square);
transform(3); // square(3)=9 → addOne(9)=10 → double(10)=20

// Memoization — cache results for performance
function memoize(fn) {
  const cache = {};
  return function(n) {
    if (n in cache) return cache[n];
    return (cache[n] = fn(n));
  };
}

const fib = memoize(n =>
  n <= 1 ? n : fib(n - 1) + fib(n - 2)
);

Chapter 09

DOM Manipulation

The DOM (Document Object Model) is the programmatic representation of your HTML page. JavaScript uses it to read, create, modify, and delete HTML elements dynamically.

INTERMEDIATE
EXAMPLE — selecting & modifying elements 
// Selecting elements
const title = document.getElementById("title");
const btn   = document.querySelector(".btn-primary");
const items = document.querySelectorAll("li.item");

// Modifying content
title.textContent = "New Title";    // plain text
title.innerHTML   = "<em>Italic</em>"; // HTML

// Modifying styles
title.style.color      = "blue";
title.style.fontSize  = "24px";
title.style.display   = "none"; // hide it

// Classes
btn.classList.add("active");
btn.classList.remove("hidden");
btn.classList.toggle("dark");
btn.classList.contains("active"); // → true

// Creating & inserting elements
const li = document.createElement("li");
li.textContent = "New item";
li.className = "item";
document.querySelector("ul").appendChild(li);

// Events
btn.addEventListener("click", (event) => {
  console.log("Clicked!", event.target);
  event.preventDefault(); // stop default behavior
});

// Event delegation — one listener for many children
document.querySelector("ul").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    e.target.classList.toggle("done");
  }
});

Chapter 10

Async JavaScript

JavaScript is single-threaded but handles asynchronous operations (network requests, timers, file reads) gracefully using callbacks, Promises, and the modern async/await syntax.

INTERMEDIATE

Promises

EXAMPLE — promises 
// A Promise represents a future value
const fetchData = () =>
  new Promise((resolve, reject) => {
    setTimeout(() => {
      const data = { id: 1, name: "Alice" };
      resolve(data); // success
      // reject(new Error("Network error")); // failure
    }, 1000);
  });

// .then().catch() pattern
fetchData()
  .then(data => console.log(data))
  .catch(err => console.error(err))
  .finally(() => console.log("Done"));

async / await

EXAMPLE — async/await with fetch API 
// async/await is "syntactic sugar" over Promises
async function getUser(id) {
  try {
    const response = await fetch(`https://api.example.com/users/${id}`);

    if (!response.ok) {
      throw new Error(`HTTP error: ${response.status}`);
    }

    const user = await response.json();
    return user;

  } catch (error) {
    console.error("Failed to fetch user:", error);
  }
}

// Running multiple Promises in parallel
async function loadDashboard() {
  const [user, posts, notifications] = await Promise.all([
    getUser(1),
    getPosts(1),
    getNotifications(1)
  ]);
  // all three complete before continuing
}
⚡
Await only works inside async functions

You can't use await at the top level of a regular script. Either wrap it in an async function, or use top-level await inside ES modules (type="module").

Chapter 12

Error Handling

Robust programs anticipate failure. JavaScript provides try/catch/finally for synchronous errors and .catch() / try-catch with await for async ones.

INTERMEDIATE
EXAMPLE — error handling patterns 
// try / catch / finally
function parseJSON(str) {
  try {
    const result = JSON.parse(str);
    return { ok: true, data: result };
  } catch (error) {
    return { ok: false, error: error.message };
  } finally {
    console.log("parseJSON finished"); // always runs
  }
}

parseJSON('{"name":"Alice"}');  // → { ok: true, data: {...} }
parseJSON("not json");         // → { ok: false, error: "..." }

// Custom Error classes
class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name  = "ValidationError";
    this.field = field;
  }
}

function validateAge(age) {
  if (typeof age !== "number")
    throw new ValidationError("age", "Must be a number");
  if (age < 0 || age > 150)
    throw new ValidationError("age", "Must be 0–150");
  return true;
}

try {
  validateAge(-5);
} catch (e) {
  if (e instanceof ValidationError) {
    console.log(`Field '${e.field}': ${e.message}`);
  } else {
    throw e; // re-throw unexpected errors
  }
}
✅
Error Handling Best Practices

Only catch errors you can handle. Re-throw errors you don't know how to handle. Use custom error classes to distinguish error types. Always handle promise rejections.

Chapter 13

Prototypes & this

Under the hood, JavaScript uses prototype chains for inheritance. The this keyword is one of JS's most confusing aspects — its value depends entirely on how a function is called, not where it's defined.

INTERMEDIATE

How Prototypes Work

Every JavaScript object has an internal link to another object called its prototype. When you access a property, JS walks up the chain until it finds it or reaches null.

EXAMPLE — prototype chain 
const animal = {
  breathe() { return "inhale... exhale..."; }
};

const dog = Object.create(animal); // dog's prototype = animal
dog.name = "Rex";
dog.bark = () => "Woof!";

dog.bark();    // → "Woof!"    (own property)
dog.breathe(); // → "inhale..." (from prototype!)

// Check prototype
Object.getPrototypeOf(dog) === animal; // → true

Understanding this

🎯
The Golden Rule of this

this is determined by how the function is called, not where it's defined. Arrow functions are the exception — they inherit this from their surrounding lexical scope.

EXAMPLE — this in different contexts 
// 1. Method call — this = the object before the dot
const obj = {
  value: 42,
  getValue() { return this.value; }
};
obj.getValue(); // → 42

// 2. Lost context — this becomes undefined (strict) or global
const fn = obj.getValue;
fn(); // → undefined (lost `this`!)

// Fix 1: bind() — permanently bind this
const bound = obj.getValue.bind(obj);
bound(); // → 42 ✓

// Fix 2: Arrow function — uses enclosing this
class Timer {
  constructor() {
    this.ticks = 0;
  }

  start() {
    // Arrow: this = Timer instance ✓
    setInterval(() => {
      this.ticks++;
      console.log(this.ticks);
    }, 1000);
  }
}

// call() and apply() — invoke with explicit this
function introduce(greeting, punctuation) {
  return `${greeting}, I'm ${this.name}${punctuation}`;
}

const user = { name: "Bob" };
introduce.call(user, "Hello", "!");         // → "Hello, I'm Bob!"
introduce.apply(user, ["Hey", "."]);        // → "Hey, I'm Bob."

Chapter 15

LocalStorage & JSON

Browsers provide LocalStorage for persisting data between page refreshes. Combined with JSON serialization, it lets you store complex objects that survive browser sessions.

INTERMEDIATE

JSON — JavaScript Object Notation

EXAMPLE — JSON serialization 
// JSON.stringify() — object → string
const user = {
  name: "Alice",
  age: 30,
  hobbies: ["coding", "hiking"],
  address: { city: "London" }
};

const json = JSON.stringify(user);
// → '{"name":"Alice","age":30,"hobbies":["coding","hiking"],...}'

const pretty = JSON.stringify(user, null, 2); // indented

// JSON.parse() — string → object
const restored = JSON.parse(json);
restored.name; // → "Alice"

// Deep clone trick (simple cases only)
const clone = JSON.parse(JSON.stringify(user));

// JSON caveats — these are dropped or changed:
JSON.stringify({ fn: () => {}, undef: undefined });
// → "{}"  (functions and undefined are silently dropped)
JSON.stringify(new Date());
// → '"2024-05-12T..."' (dates become strings)

LocalStorage API

EXAMPLE — localStorage 
// localStorage only stores strings — always JSON-encode objects

// Save
localStorage.setItem("theme", "dark");
localStorage.setItem("user", JSON.stringify({ name: "Alice" }));

// Read
const theme = localStorage.getItem("theme");     // → "dark"
const user  = JSON.parse(localStorage.getItem("user"));

// Delete
localStorage.removeItem("theme");
localStorage.clear(); // wipe everything

// Safe helper utility
const storage = {
  get(key, fallback = null) {
    try {
      const item = localStorage.getItem(key);
      return item !== null ? JSON.parse(item) : fallback;
    } catch { return fallback; }
  },
  set(key, value) {
    try { localStorage.setItem(key, JSON.stringify(value)); }
    catch (e) { console.warn("Storage full", e); }
  }
};

// Usage:
storage.set("prefs", { lang: "en", dark: true });
storage.get("prefs", { lang: "en" }); // fallback if missing
🔐
Never store sensitive data in LocalStorage

LocalStorage is accessible by any JavaScript on the page, making it vulnerable to XSS attacks. Never store passwords, tokens, or personal data there. Use httpOnly cookies for auth tokens.
